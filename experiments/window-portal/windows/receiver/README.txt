Standalone Windows Window Portal receiver

This is a separate Electron application. It does not rebuild TwinDesk, create a
display, capture the desktop, or take over the global mouse. A source endpoint
must implement docs/window-portal-wire-v1.txt. Run npm install to obtain ws 8.22.0
or use the existing verified dependency from the Windows development checkout.

Launch:
  electron <this directory> --config=<absolute private JSON file>

Private config (never commit, print or send to agent chat):
  url: wss://<source>:49731/portal
  certSha256: lowercase 64-hex SHA256 of paired DER server certificate
  token: single-use 64-hex pairing token generated by source
  sourceCommit: full 40-hex commit of this RECEIVER build
For an explicit local test only: url uses ws://127.0.0.1:<port>/portal and
loopbackTest is true. LAN never falls back to plaintext or an unpinned server.

Right-click the proxy for Minimize, Search in source, or Return window to source.
The 8px center-top grip moves the receiving window locally. Ctrl+Shift+M minimizes;
Ctrl+Shift+Q returns it. These are receiver actions, not remote shortcuts. Windows
taskbar supplies restore. Closing returns the source window, not quits its app.
Source app icon is used when provided. Input is limited to advertised press/search
operations; arbitrary typing, source titlebar management, menus and drag/drop are
not implemented. Automatic edge transfer and exact cross-machine layout are not
implemented. Disconnection disables input and leaves a clearly marked stale image.

Receiver diagnostics go to receiver-events.jsonl, without tokens. The GUI does
not depend on stdout/stderr remaining connected. profile/ holds local Electron
settings. The receiver checks pin before the hello secret is sent, validates PNG
dimensions before/after decode, waits for image installation before ACK, and only
accepts one outstanding frame. Test fixture PNGs are synthetic, not Finder proof.
